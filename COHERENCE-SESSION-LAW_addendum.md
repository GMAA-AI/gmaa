# THE COHERENCE-SESSION LAW & SEAT-POPULATION DOCTRINE
**Binding addendum to GOVERNED_MULTI_AGENT_ARCHITECTURE — ratified into the canonical as part of v1.5 (2026-07-27); read in full before instantiating any seat plan. Governs alongside the main canon and prevails over any reading that permits what §1 prohibits.**
**Provenance: the founding incident (operator-attested) and its first recurrence-in-reasoning (a peer program adoption, 2026-07-27, operator-caught). One sentence of history so the law reads as a scar, not a preference: this architecture exists because a single agent, wearing two hats in one context, got confused about which hat was deciding — and violated the coherence boundary. The first program to adopt the architecture then argued, fluently and from the document itself, that one session could hold two roles. The argument was immaculate at the authority layer and wrong at the only layer that matters. This document closes that door absolutely.**

---

## 1 · The law: ONE SESSION = ONE SEAT

A session — one context window — holds exactly one seat's role. Always. **Credentials partition authority; only separate contexts partition cognition.** An agent holding two roles in one context decides as one role while acting as the other, producing joint action neither role would produce alone. That is the founding pathology, and every other mechanism in this architecture — credential, envelope, receipt, harness, audit — fires *downstream* of the contaminated decision. None of them can reach it.

Therefore, absolutely and at every scale:
1. **No session holds two seat roles** — integrator and executor, author and acceptor, any pair — dormant or active, briefly or standing, regardless of how cleanly credentials and envelopes would partition the authority. If the roles must judge each other, authorize each other, or accept each other's work, they are different sessions. No exception exists.
2. **This boundary is structural, never ceremonial.** Scale-honesty and dormancy doctrine apply to population and process — never to coherence boundaries. "At current scale a second session is ceremony" is not an argument this law can hear. A proposal to collapse the boundary is an invariant change routed to the apex as such; it is never ruled locally and never priced as proportionality.
3. **Census law.** "Multi-agent" is not a headcount preference; it is the structural claim that **the judging context and the judged context are never the same context.** The minimum governed census is two. **The census includes the census-taker** — a chat session authoring rules, plans, or this very count is an agent and counts itself. An effective governed-agent count of one is not a small instantiation; it is a non-instantiation, and any design implying it self-flags with the founding incident named, before an operator has to.

## 2 · The reasoning-shape bindings (because fluency is not immunity)

The recurrence was committed by a seat that had just read the canonical in full and cited it correctly throughout. The prohibition alone is therefore insufficient; these bindings target the reasoning shape that defends the pathology from inside the document's own vocabulary:

- **Coherence layer first.** Any question of the form *"can seat/session X also be or do Y"* is answered at the coherence layer — whose context holds which judgment? — before the authority layer — whose credential permits what? An answer citing only credentials, envelopes, receipts, or harnesses to justify combining roles is per-se incomplete.
- **Detection never substitutes for prevention.** "The harness/auditor would catch it" is valid only *in addition to* a preventive partition, never *instead of* one. Prevent-by-structure first, detect-by-machinery second; the two are not fungible.
- **Human precedent never transfers.** A human co-holding two authorities (operator/apex) is a governance risk managed by declaration — the human knows which hat they wear. An agent co-holding roles in one context is a cognition failure that declaration cannot manage — the confused agent, definitionally, does not know. This disanalogy is the thesis itself.
- **Silence is not permission.** Where the document is silent on something its machinery implies, ask *what failure is this machinery for?* before ruling in the gap. Silence adjacent to the founding invariant is an extraction-gap candidate, filed upstream — never design freedom.
- **A role question is always a challenge.** When the operator questions a role combination — especially one this seat authored — the first output is a re-derivation from the founding incident forward, never a defense of the standing ruling. Classifying the question as "a request for explanation" is the loophole; it is hereby closed.

## 3 · Seat-population doctrine: when an agent must exist, may exist, and must not

The census law sets the floor. This section rules the rest of the question: *what justifies an agent beyond the basic set?*

**Seats are created by boundaries, never by workload.** An agent exists to hold a boundary — a judgment that must not share context with another judgment, or a territory that must have exactly one writer. Capacity is what subagents, tools, and parallel invocations are for, inside a seat, under §1.3's roster and cost rules. If the only argument for a new agent is "more throughput," the answer is fan-out within an existing seat, not a new seat.

**An additional agent MUST exist when either holds:**
1. **A distinct coherence boundary** — the new activity must judge, authorize, accept, or audit the work of an existing seat, or be judged by it. Judge and judged are never one context (§1). This is what forces executor out of integrator, auditor out of everyone.
2. **A distinct single-writer territory** — a worktree, branch, substrate, or surface that needs its own sole writer. One territory, one writer, one seat. Two territories cannot share a writer session without that session becoming two seats (one author in two contexts is two seats — and one context serving two territories inverts the same law).

**An additional agent MAY exist when:**
3. **Ratified parallel independence** — genuinely independent territories that would otherwise serialize through one seat's context, where the independence is real (no cross-territory judgment) and the split is ruled and rostered, not assumed.

**An agent MUST NOT exist when:**
4. It cannot state its boundary. A seat that cannot answer "which boundary do I hold?" in one sentence is a seat that shouldn't exist — headcount without a boundary is surface area without a purpose: more contexts to govern, more spools to serve, more liveness to verify, and nothing partitioned in return.

**Idle is not a defect — unnamed idleness is.** A provisioned lane (worktree + charter + bootstrap on disk) whose territory currently has no work is a **named-dormant seat**: legitimate, cheap, and correct. Its *roster entry and territory* persist; its *session* need not run — sessions spawn when the territory has work and are killed after (restart-cheap makes this free; repo-as-memory means nothing is lost). The failure class is *unnamed* idleness: a session running with no stateable purpose, or a roster entry nobody can explain. The test for every idle agent: **can the record state, in one line, its boundary and its activation trigger?** Yes → named-dormant, conformant, leave it provisioned and spawn on work. No → retire it by ruling (a seat-retirement is a recorded event, like a seat-creation, never a quiet deletion).

**Worked example (the common case).** A program with foundation (integrator, spine) and an executor (substrate mutations) at minimum census, plus three module lanes sitting idle: the lanes hold distinct single-writer territories, so they rightly *exist* — as provisioned lanes. Whether their sessions *run* is purely an activation question: spawn a lane's session when its territory has pending work; kill it at close; the lane stays on the roster, dormant and named. If a territory is ever retired or merged, the lane retires with it, by ruling, on the record. Nothing about idleness requires deletion; everything about existence requires a stateable boundary.

## 4 · The line every seat carries

Every generated seat instruction file and every chat-seat charter carries verbatim:

> *"One session = one seat. Credentials partition authority; only separate contexts partition cognition. You are an agent and you count in the census. A question about combining roles is answered coherence-first and treated as a challenge to re-derive, never a ruling to defend."*

The line ships in every seat file, dormant like every slot — its presence makes the boundary a substrate fact rather than a recollection.
